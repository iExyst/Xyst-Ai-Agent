# Project review — 2026-10-29

Baseline: `1e5459c` on `codex/xyst-ai-assistant-v0.1.2` in `iExyst/Xyst-Ai-Agent`.

## Scope

Project-wide JavaScript syntax, lint, and automated tests; Windows Rust compilation; browser integration checks; and manual inspection across the agent loop, provider adapters, API request/event contracts, configuration, session/context persistence, process/path handling, desktop navigation, and extension integration. Vendored dependencies were not edited. This is a code and regression review, not a claim that every possible execution path has been exercised.

## Repairs

- Search fallback now handles provider outages and rate limits as well as missing/rejected credentials. Invalid queries and explicit user cancellation do not launch a fallback request.
- Search deduplication preserves case-sensitive URL paths and query values, while still deduplicating fragments of the same page.
- Weather lookup asks for clarification when same-name cities occur in different states within one country, rather than silently choosing the first city.
- Internet guidance is only included when the relevant tools are available, and duplicated weather instructions are removed. This restores a delegated-task retry that previously exhausted its shared input budget before reaching the model.
- Switching from Settings to a conversation clears the previous sidebar category highlight.
- Workspace tool controls remain in the document and visible during conversations instead of being detached with the home dashboard. They return to the dashboard on a new conversation.
- The recent-conversation list keeps a minimum usable height when sidebar navigation occupies most of a short window.
- Browser and API checks now follow the current sidebar navigation, inline settings editor, collapsed model discovery, and theme, instead of expecting the removed Advanced Settings dialog and obsolete labels.

## Follow-up: compaction continuity and connection reporting

- Compaction now selects the largest complete oldest prefix that fits the summary model without dropping any of its turns. Only that prefix is archived and removed; unsummarized turns stay active. Histories larger than the summary model's window can be compacted incrementally.
- Operation-level API errors no longer imply an offline runtime. Transport/local errors trigger a bounded health check, stale health results cannot overwrite newer connection evidence, and run cleanup does not infer connectivity from the visibility of an error banner.
- Validation: 8 compaction tests and 11 related agent/context/budget tests passed; lint passed. Browser smoke passed with added checks for a healthy-service 404, a simulated transport outage, and successful reconnection, alongside the existing integration coverage.

## Follow-up: live lookup dates and retries

The user's failed news lookup had searched October 2024 and treated returned 2026 articles as future-dated. The next retry timed out in the local model before making a new tool call. Live-lookup instructions now begin with the runtime date, include that date in the initial required-search turn, and recognize short retries referring to the preceding live-information question. Such retries retain the saved transcript but build their lookup context from the resolved user question and fresh tool evidence, rather than repeating incorrect earlier assistant claims.

Two duplicate Qwen 9B instances were unloaded from LM Studio while preserving the selected instance. A retry using an isolated copy of the actual chat then completed, searched for October 29, 2026, and retrieved live web results. This verifies tool access and current-date handling; it is not an independent verification of every factual claim generated by the model. All 119 agent tests and repository lint passed after the change.
